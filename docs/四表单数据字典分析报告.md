# 四表单数据字典分析报告

> 范围:templates-src/html/ 四张表单(登记表/变更表/验收登记表/验收报告)逐字段过审
> 基线:sc_backend data.sql 现有字典 7 类 31 行(hx_project_type / client_nature / hx_outcome_form / change_type / budget_subject_hx / member_type / hx_scan_doc_type)
> 日期:2026-10-19

## 一、结论摘要

| 判定 | 数量 | 说明 |
|---|---|---|
| **已被字典覆盖**(核对一致,无需动作) | 6 处勾选组/科目行 | 项目类型、委托单位性质、成果形式、变更类型、预算科目、成员类型 |
| **建议新增字典** | **1 类** | 职称(成员表,四表中两处复用) |
| **不建议入字典**(布尔/自由文本/系统数据/规则生成) | 4 类 | 见第五节,各有理由 |
| **规范债(建议处理)** | 3 处命名 | client_nature / change_type / member_type 无模块前缀,违决策#32 |

## 二、判定口径(什么字段适合做成数据字典)

1. **封闭有限集合**:取值可穷举(≤10 项左右),不随业务数据无限增长;
2. **多处复用**:同一集合在 ≥2 张表单或前后端校验/模板渲染多处出现;
3. **业务可调**:科技处可能增删停用(此时改管理页,不改代码);
4. **无顺序/联动逻辑依赖**:字典只管"有哪些",不管"选中后干什么"(那属于代码逻辑)。

不满足任一条的,用布尔字段、自由文本、组织表(sys_dept)、用户表(sys_user)或编号规则承载。

## 四、建议新增:职称字典

- **理由**:登记表与验收表成员表两处复用;集合封闭(职称序列全国统一口径);填写频繁、错别字多(现自由文本),入字典后可下拉选择+管理页维护。
- **dict_type 建议**:`title`(平台级——纵向模块今后同样要用,故不带 hx_ 前缀;与决策#32 的模块前缀规则并存:平台级通用字典用裸名,业务专属带前缀)。
- **初始值集**(种子,管理页可增删):

| value=label | 说明 |
|---|---|
| 教授 / 副教授 / 讲师 / 助教 | 高校教师序列 |
| 研究员 / 副研究员 | 科研序列 |
| 正高级工程师 / 高级工程师 / 工程师 / 助理工程师 | 工程序列(校外人员常用) |
| 正高级实验师 / 高级实验师 / 实验师 | 实验技术序列 |
| 其他 | 兜底(与各勾选组"其他"口径一致) |

- **注意**:存量 rp_member.title 已有自由文本数据,切换字典后需一次性数据对齐(模糊匹配+人工兜底);前端改为下拉(可搜索),教师端/管理端同源。

## 五、不建议入字典的边界字段(及理由)

| 字段 | 理由 | 载体建议 |
|---|---|---|
| 专业/学科专业 | 目录庞大且随教育部目录调整;表单仅作展示不需按专业统计(如需统计再立专项) | 自由文本 |
| 是否类(设备场地/收取管理费/按期完成) | 封闭二元、无业务增删诉求;入字典徒增一次查库 | 布尔字段,前端固定"是/否"选项 |
| 委托单位名称(名录) | **开放集合、按业务无限增长**——字典管理页不适合维护名录;且同名单位需区分 | 自由文本+历史录入提示(输入联想去重),数据量上来后可立"单位名录参考表" |
| 项目编号 | 由规则生成(HX{年}-{序}),非枚举 | 编号规则代码;若纵向启用不同前缀,前缀入 sys_config |

## 六、现有字典命名规范债(建议 N5 前处理)

决策#32 要求"字典 dict_type 带模块前缀",现状不一致:

| 现名 | 问题 | 建议 |
|---|---|---|
| `client_nature` | 无前缀,但内容纯属横向 | `hx_client_nature` |
| `change_type` | 同上 | `hx_change_type` |
| `member_type` | 同上 | `hx_member_type` |
| `budget_subject_hx` | 前缀作后缀,风格不统一 | `hx_budget_subject` |
| `hx_project_type` / `hx_outcome_form` / `hx_scan_doc_type` | 合规 | 不动 |

迁移影响:后端引用处(dict_type 字符串、模板勾选组取数)、data.sql 种子、模板占位符清单同步;纯重命名+数据 UPDATE,无表结构变化。**改名与"职称新字典"同批做,一次种子重置**。

## 七、HTML 演示新交互 → 落地数据设计提示(非字典但相关)

| 演示交互 | 落地载体 |
|---|---|
| 预算行"合同约定不受限"(勾选后金额不可填) | rp_budget 行级 flag 列(unrestricted TINYINT),勾选时 amount 置空;渲染层口径文字 |
| 预算合计实时计算 | 后端 SUM(不受限行排除)+前端同口径即时算 |
| 管理费默认比例 2% | `sys_config` 数值型配置(如 mfee_default_rate),与 deliver_pdf_visible 同类,**不是字典** |
| 变更内容自动带出原信息 | 代码按 change_type → 字段映射(经费→rp_hx_project.contractAmount 等),非字典 |
| 验收报告"是否按期完成" | 布尔列(如 rp_hx_flow 验收字段或 report 扩展) |

## 八、落地口径(沿用现有机制)

1. 新字典/改名一律走 data.sql `INSERT IGNORE` 固定 id 种子(Task26 口径):管理页停用/调序/改名重启不重置;
2. 前后端校验同源:后端按 dict 校验合法值(参照 changeType/outcomeForm 现有 split 校验),前端下拉/勾选组从同一字典取数;
3. 模板勾选组渲染按字典序(sort_order),停用项不出现在新单据、历史单据照旧显示。

---
*结论:四表单字段与现有 7 类字典基本对齐,真正缺口只有"职称"一类;另建议顺手清理 3 处命名前缀规范债。*

> **实施记录(2026-10-19)**:第四节职称字典与第六节改名已全部落地——title 14 项种子入库(id 1081-1094);四处改名经 data.sql UPDATE 幂等迁移(存量库重启即生效);前后端引用同步;登记向导职称改字典下拉(可选可输)。验证:JUnit 31/31 + /dicts 新旧名 9 项核对 + admin39/register22/change_accept12 接口全绿。
